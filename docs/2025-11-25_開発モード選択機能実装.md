## ✨ 新機能

### 1. 開発モード選択Enum (`DevelopmentMode`)

**ファイル**: `codex-rs/core/src/orchestration/development_mode.rs`

**実装内容**:
- `DevelopmentMode::Central` - 中央集権型オーケストレーション
  - `MergeStrategy`によるコンフリクト解決
  - 動的コンフリクト検出
  - `ConflictResolver`によるデッドロック防止
- `DevelopmentMode::Worktree` - Git worktree型並列開発
  - 並列worktree数指定
  - 勝者自動マージ機能

**主要API**:
```rust
pub enum DevelopmentMode {
    Central {
        merge_strategy: MergeStrategy,
        dynamic_conflict_detection: bool,
    },
    Worktree {
        num_worktrees: usize,
        auto_merge_winner: bool,
    },
}

impl DevelopmentMode {
    pub fn to_execution_mode(&self) -> ExecutionMode;
    pub fn description(&self) -> &'static str;
}
```

### 2. 過去の実装ログ分析機能

**実装内容**:
- `_docs/`ディレクトリから実装ログを読み込み
- ファイル名から日付と機能名を抽出
- マークダウンコンテンツからサマリーと詳細を抽出
- 日付順にソート（新しい順）

**主要API**:
```rust
pub struct DevelopmentModeSelector {
    repo_root: PathBuf,
    logs_dir: PathBuf,
}

impl DevelopmentModeSelector {
    pub fn analyze_implementation_logs(&self) -> Result<Vec<ImplementationLog>>;
    pub fn analyze_commit_history(&self, keywords: &[&str], limit: usize) -> Result<Vec<CommitEntry>>;
    pub fn recommend_mode(&self) -> Result<DevelopmentMode>;
}
```

### 4. 開発モード推奨機能

**実装内容**:
- 実装ログとコミット履歴を分析
- 中央集権型とworktree型の参照回数をカウント

**アルゴリズム**:
1. 実装ログから「orchestration」「central」「conflict」キーワードを検索

## 🚀 主要機能

### 開発モード選択

#### 中央集権型オーケストレーション (`Central`)
- **用途**: 同一リポジトリでの複数エージェント協調
- **特徴**:
  - `ConflictResolver`によるデッドロック防止
  - 動的コンフリクト検出
  - `MergeStrategy`によるコンフリクト解決
    - `Sequential` - 順次実行（安全だが遅い）
    - `ThreeWayMerge` - 3-wayマージ（高速だが失敗する可能性）
    - `LastWriteWins` - 最後の書き込みが優先（高速だが危険）

#### Git Worktree型並列開発 (`Worktree`)
- **用途**: 並列バリアント開発、競合最適化
- **特徴**:
  - 各エージェントに独立したworktreeを作成
  - 分離されたブランチで作業
  - 勝者を自動マージ

### 過去の実装ログ分析

**実装ログ形式**: `yyyy-mm-dd_機能名.md`

**抽出情報**:
- 日付（ファイル名から）
- 機能名（ファイル名から）
- サマリー（マークダウンの最初の見出しまたは段落）
- 詳細（キー:値のペア）

**例**:
```
2025-11-05_Dynamic-Agent-Orchestration.md
→ date: "2025-11-05"
→ feature: "Dynamic-Agent-Orchestration"
→ summary: "Dynamic AI Agent Orchestration with Resource Management"
```

### Gitコミット履歴分析

**検索キーワード**:
- 中央集権型: `orchestration`, `orchestrated`, `central`, `conflict`
- Worktree型: `worktree`, `parallel`, `competition`, `variant`

**取得情報**:
- コミットSHA
- コミットメッセージ
- 作者
- 日付
- 変更ファイル一覧

## 🔍 技術詳細

### 実装ログ解析フロー

```
1. _docs/ディレクトリをスキャン
   ↓
2. .mdファイルを検出
   ↓
3. ファイル名から日付と機能名を抽出
   ↓
4. マークダウンコンテンツを解析
   ├─ 最初の見出しをサマリーとして抽出
   └─ キー:値のペアを詳細として抽出
   ↓
5. ImplementationLogとして返却
```

### Gitコミット履歴解析フロー

```
1. git logコマンドを実行
   ├─ キーワードでフィルタリング
   └─ フォーマット: %H|%s|%an|%ai
   ↓
2. 各行をパース
   ├─ SHA抽出
   ├─ メッセージ抽出
   ├─ 作者抽出
   └─ 日付抽出（RFC3339形式）
   ↓
3. git showコマンドで変更ファイルを取得
   ↓
4. CommitEntryとして返却
```

### 開発モード推奨アルゴリズム

```
1. 実装ログを分析
   ├─ 中央集権型キーワードを検索
   └─ Worktree型キーワードを検索
   ↓
2. Gitコミット履歴を分析
   ├─ オーケストレーション関連コミットを検索
   └─ Worktree関連コミットを検索
   ↓
3. 参照回数をカウント
   ├─ central_refs = 実装ログの中央集権型参照 + オーケストレーションコミット数
   └─ worktree_refs = 実装ログのWorktree型参照 + Worktreeコミット数
   ↓
4. 参照回数が多い方を推奨
   ├─ worktree_refs > central_refs → Worktreeモード推奨
   └─ それ以外 → Centralモード推奨
```

## 📊 使用例

### 開発モード選択

```rust
use codex_core::orchestration::{DevelopmentMode, DevelopmentModeSelector};

// セレクター作成
let selector = DevelopmentModeSelector::new(".")?;

// 過去の実装ログを分析
let logs = selector.analyze_implementation_logs()?;
println!("Found {} implementation logs", logs.len());

// Gitコミット履歴を分析
let commits = selector.analyze_commit_history(&["orchestration", "worktree"], 20)?;
println!("Found {} relevant commits", commits.len());

// 推奨モードを取得
let recommended_mode = selector.recommend_mode()?;
println!("Recommended mode: {:?}", recommended_mode);
println!("{}", selector.get_mode_summary(&recommended_mode));
```

### 開発モードの使用

```rust
use codex_core::orchestration::{DevelopmentMode, MergeStrategy};

// 中央集権型モード
let central_mode = DevelopmentMode::Central {
    merge_strategy: MergeStrategy::ThreeWayMerge,
    dynamic_conflict_detection: true,
};

// Worktree型モード
let worktree_mode = DevelopmentMode::Worktree {
    num_worktrees: 3,
    auto_merge_winner: true,
};

// ExecutionModeに変換
let execution_mode = central_mode.to_execution_mode();
assert_eq!(execution_mode, ExecutionMode::Orchestrated);
```
