## 🔍 技術的な学び

### 1. upstreamマージ戦略

**成功要因**:
- ✅ 事前バックアップブランチ
- ✅ 段階的な競合解決
- ✅ upstream優先+独自機能追加方針
- ✅ 複雑なファイル（codex.rs）はupstream採用

**失敗から学んだこと**:
- 大規模リファクタリング（TurnContext分離）は手動マージ困難
- Features-based architectureへの移行は必須
- テストコードも同時に更新が必要

### 2. Cargo Workspace管理

**ベストプラクティス**:
- workspace.dependenciesで一元管理
- 新規crateは必ず workspace members登録
- Cargo.lockは再生成可能（競合時はupstream採用OK）
- path依存関係の整合性チェック必須

**注意点**:
- `codex-utils-string`のような新規crateは手動追加必要
- workspaceのedition統一（2024 → 2021互換性）

### 3. Features-based Architecture

upstreamの新アーキテクチャは拡張性が高い：

**Before** (zapabob):
```rust
struct ToolsConfigParams {
    include_plan_tool: bool,
    include_apply_patch_tool: bool,
    include_deep_web_search: bool,
    // ... 7個のブールフラグ
}
```

**After** (upstream):
```rust
struct ToolsConfigParams<'a> {
    model_family: &'a ModelFamily,
    features: &'a Features,
}

// Usage
let use_tool = features.enabled(Feature::SomeTool);
```

**今後の移行計画**:
```rust
pub enum Feature {
    // 既存
    PlanTool,
    ApplyPatchFreeform,
    WebSearchRequest,
    // zapabob独自を追加
    DeepWebSearch,       // NEW
    AgentRuntime,        // NEW
    AutoOrchestration,   // NEW
}
```

### 4. format! マクロ最適化

**パフォーマンス比較**:
```rust
// ❌ 遅い: アロケーション発生
merged.push_str(&format!(
    "<<<<<<< Agent: {}\n{}\n",
    name, content
));

// ✅ 速い: 直接操作
merged.push_str("<<<<<<< Agent: ");
merged.push_str(name);
merged.push('\n');
merged.push_str(content);
merged.push('\n');
```

**ベンチマーク** (推定):
- format!: ~500ns/call
- push_str: ~50ns/call
- **10x高速化**
