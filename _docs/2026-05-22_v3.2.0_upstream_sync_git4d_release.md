## Overview

This log records the v3.2.0 sync line. The release imports the latest official Codex changes, preserves zapabob-specific Git4D and plugin value, and keeps the fork on official app-server and protocol surfaces.

## Background / Requirements

- Import official Codex features, vulnerability updates, and bug fixes from upstream.
- Preserve fork-only value only where it remains useful.
- Prefer official APIs when the official and custom behavior overlap.
- Use a Python merge script and preserve a durable merge report.
- Bump the semantic version for the fork release.
- Validate with Rust formatting, check, and focused integration tests before packaging.

## Assumptions / Decisions

- `3.2.0` is a minor release because the fork adds official upstream features and keeps the existing extension model compatible.
- Official upstream remains the product baseline.
- Git4D belongs behind app-server protocol methods and plugin-facing clients, not as a replacement for the official app.
- AR/VR runtime absence is a supported state and must return a desktop fallback instead of failing the request.
- App-server child processes must not print non-JSON text to stdout because stdout is the JSON-RPC transport.
