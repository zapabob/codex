# 差分から発見したRust依存関係管理ベストプラクティス

**日時**: 2025-11-28 15:05:00
**タスク**: CLI起動テスト中の依存関係問題から学ぶベストプラクティス

## 現在の問題状況分析

### 発生した依存関係問題
1. **Protocol Re-export**: `crate::protocol` として参照できない
2. **Missing Dependencies**: rmcp-client, execpolicy, multimap, starlarkなど
3. **循環依存**: deep-research ↔ core の依存関係ループ
4. **Workspace定義漏れ**: 多くのdependenciesがworkspaceで未定義

### 適用した解決策

#### 1. Protocol Re-exportの戦略的修正

**問題**: `codex_protocol::*` をre-exportしても `crate::protocol` アクセス不可

**解決策**:
```rust
// lib.rs
// 直接アクセス用
pub use codex_protocol::*;

// crate::protocol アクセス用
pub use codex_protocol::protocol;
```

**ベストプラクティス**: 複数のアクセスパターンをサポートするために、両方のre-exportを行う

#### 2. Feature Gatesによる依存関係制御

**問題**: rmcp-clientが存在しない場合のコンパイルエラー

**解決策**:
```toml
# Cargo.toml
[features]
default = []
rmcp = ["codex-rmcp-client"]

# lib.rs
#[cfg(not(feature = "rmcp"))]
pub mod rmcp_client_stub { /* スタブ実装 */ }
#[cfg(not(feature = "rmcp"))]
pub use rmcp_client_stub::*;
```

**ベストプラクティス**: Optional dependenciesをfeature flagで制御し、利用できない場合にスタブを提供

#### 3. Workspace Dependenciesの一元管理

**問題**: multimap, starlarkなどのdependenciesがworkspaceで未定義

**解決策**:
```toml
# workspace Cargo.toml
multimap = "0.10"
starlark = "0.10"
```

**ベストプラクティス**: 全ての共有dependenciesをworkspaceで一元管理し、バージョン競合を防ぐ

#### 4. 循環依存関係の解決

**問題**: deep-research ↔ core の相互依存

**解決策**:
```toml
# 一時的に依存を無効化
# codex-deep-research = { path = "../deep-research" }
```

**ベストプラクティス**: 循環依存が発生した場合、機能を段階的に有効化し、アーキテクチャを再設計

#### 5. 条件コンパイルの適切な使用

**問題**: execpolicyが存在しない場合のコンパイルエラー

**解決策**:
```rust
#[cfg(feature = "execpolicy")]
use codex_execpolicy::Policy;
#[cfg(not(feature = "execpolicy"))]
use crate::Policy; // スタブ
```

**ベストプラクティス**: 条件コンパイルを活用し、依存関係の有無で実装を切り替え

## 導き出されたベストプラクティス

### 1. Workspace Management

#### ✅ DO: 共有Dependenciesの一元管理
```toml
# workspace/Cargo.toml
[workspace.dependencies]
multimap = "0.10"
starlark = "0.10"
serde = { version = "1.0", features = ["derive"] }
```

#### ❌ AVOID: 個別クレートでの直接指定
```toml
# 各クレートで個別に指定するとバージョン競合が発生
multimap = "0.10"  # workspaceで管理すべき
```

### 2. Feature Gates Strategy

#### ✅ DO: Optional DependenciesのFeature制御
```toml
[features]
default = []
rmcp = ["codex-rmcp-client"]
execpolicy = ["codex-execpolicy"]
```

#### ✅ DO: スタブ実装の提供
```rust
#[cfg(not(feature = "rmcp"))]
pub mod rmcp_stub {
    pub struct RmcpClient;
    // 最小限のインターフェース実装
}
```

### 3. Protocol Re-export Patterns

#### ✅ DO: 複数アクセスパターンのサポート
```rust
// lib.rs
pub use codex_protocol::*;        // 直接アクセス
pub use codex_protocol::protocol; // crate::protocol アクセス
```

#### ✅ DO: 条件付きRe-export
```rust
#[cfg(feature = "protocol")]
pub use codex_protocol;
```

### 4. 循環依存関係の回避

#### ✅ DO: 段階的依存関係有効化
```toml
# Phase 1: 基本機能のみ
codex-core = { path = "../core" }

# Phase 2: 拡張機能を追加
# codex-deep-research = { path = "../deep-research" }
```

#### ✅ DO: Interface Segregation
循環依存が発生したら、機能を別クレートに分割するか、interfaceクレートを作成

### 5. 条件コンパイルBest Practices

#### ✅ DO: クリーンな条件分岐
```rust
#[cfg(feature = "advanced")]
use crate::advanced_features::*;
#[cfg(not(feature = "advanced"))]
use crate::basic_features::*;
```

#### ❌ AVOID: 複雑な条件ネスト
```rust
#[cfg(all(feature = "a", not(feature = "b"), any(feature = "c", feature = "d")))]
// 読みにくく保守しにくい
```

### 6. Error Handling Strategy

#### ✅ DO: コンパイル時エラーの予防
```rust
// 依存関係が見つからない場合のフォールバック
#[cfg(not(feature = "external_dep"))]
mod fallback_impl {
    pub fn external_function() { /* stub */ }
}
```

#### ✅ DO: 段階的ビルド検証
```bash
# 段階的に問題を解決
cargo check -p core-base    # 基本機能のみ
cargo check -p core-ext     # 拡張機能を追加
cargo check -p full-app     # 完全ビルド
```

## 学習した教訓

### 1. Workspace Dependenciesの重要性
- 共有dependenciesをworkspaceで一元管理することで、バージョン競合を防ぎ、保守性を向上

### 2. Feature Gatesの戦略的活用
- Optional dependenciesをfeatureで制御することで、ビルドを柔軟にカスタマイズ可能

### 3. 段階的実装アプローチ
- 全ての機能を同時に有効化しようとせず、段階的に問題を解決

### 4. スタブ実装の有効性
- 依存関係が利用できない場合でも、コンパイルを継続できるようにスタブを提供

### 5. 循環依存の早期発見
- 定期的な依存関係チェックを行い、循環依存を早期に発見・修正
