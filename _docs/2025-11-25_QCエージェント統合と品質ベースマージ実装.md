## 🎯 概要

中央集権型（Central）と並列開発型（Worktree）の両方で、QCエージェントをサブエージェントとして統合し、QC管理・量子最適化・数理最適化による品質スコア計算を行い、最も品質の高いコードをログに記録してマージする機能を実装したで！

### 2. QCエージェント実行ロジック実装

**ファイル**: `codex-rs/core/src/orchestration/parallel_execution.rs`

**実装内容**:
- `run_qc_agent`メソッドを追加
- `QcAgent::analyze()`を呼び出してコード品質分析を実行
- worktreeまたは現在のディレクトリからソースコードを読み込み
- QC結果（QcReport, QualityScore）をJSON形式で返却

**主要機能**:
- ソースファイルの自動検出（Rust, TypeScript, JavaScript）
- 統計分析、量子最適化、数理最適化の実行
- 品質スコアの計算（可読性、保守性、パフォーマンス、セキュリティ）

### 3. 品質スコアベースのマージ機能実装

**ファイル**: `codex-rs/core/src/orchestration/qc_merger.rs` (新規)

**実装内容**:
- `QcMerger`構造体を作成
- 中央集権型用: `select_best_central()` - 複数エージェントの結果をQC評価して最も品質の高いものを選択
- 並列開発型用: `select_best_worktree()` - 各worktreeの結果をQC評価して最も品質の高いworktreeをマージ
- 品質スコア比較ロジック（`QualityScore::overall`を使用）

**主要API**:
```rust
pub struct QcMerger {
    qc_agent: Arc<QcAgent>,
}

impl QcMerger {
    pub async fn select_best_central(&self, results: Vec<AgentResult>) -> Result<(AgentResult, HashMap<String, QualityScore>)>;
    pub async fn select_best_worktree(&self, worktrees: Vec<WorktreeInfo>) -> Result<(WorktreeInfo, HashMap<String, QualityScore>)>;
}
```

### 4. QC結果のログ記録機能

**ファイル**: `codex-rs/core/src/orchestration/qc_logger.rs` (新規)

**実装内容**:
- `QcLogger`構造体を作成
- QC結果を実装ログ形式で`_docs/`ディレクトリに保存
- 品質スコア、最適化結果、推奨事項を記録
- マージ決定の根拠を記録

**主要API**:
```rust
pub struct QcLogger {
    logs_dir: PathBuf,
}

impl QcLogger {
    pub async fn log_qc_result(&self, report: &QcReport, merge_decision: &str) -> Result<PathBuf>;
    pub async fn log_merge_decision(&self, selected: &str, scores: &HashMap<String, QualityScore>) -> Result<PathBuf>;
}
```

**ログ形式**:
- QC分析レポート: `yyyy-mm-dd_HH-MM-SS_qc_analysis.md`
- マージ決定ログ: `yyyy-mm-dd_HH-MM-SS_qc_merge_decision.md`

```
6. 結果を統合して返却
```

```
6. QcLoggerでマージ決定をログに記録
```

## 🚀 主要機能

### QCエージェントの並列実行

- **中央集権型**: 他のエージェントの結果を分析
- **並列開発型**: 各worktreeのコードを分析
- **分析内容**:
  - 統計分析（コード統計、品質指標）
  - 量子最適化（最適化提案、改善ポテンシャル）
  - 数理最適化（リソース割り当て、ボトルネック分析）

### 品質スコアベースの選択

**品質スコアの計算**:
- **可読性**: コード密度、関数サイズ
- **保守性**: 複雑度、インポート効率
- **パフォーマンス**: 最適化ポテンシャル
- **セキュリティ**: リソース最適化スコア
- **総合スコア**: 上記4つの平均

**選択アルゴリズム**:
1. 各エージェント/worktreeのコードをQC分析
2. 品質スコアを計算
3. 総合スコアが最も高いものを選択
4. マージ決定をログに記録

### QC結果のログ記録

**ログ内容**:
- QC分析レポート
  - 品質スコア（総合、可読性、保守性、パフォーマンス、セキュリティ）
  - 統計分析メトリクス
  - 量子最適化結果
  - 数理最適化結果
  - 推奨事項
  - マージ決定の根拠

- マージ決定ログ
  - 品質スコア比較表
  - 選択理由
  - 詳細メトリクス（JSON形式）

```
   ↓
2. QcAgent::analyze()を実行

   ├─ 数理最適化

   ↓

```

```
1. 各エージェントの結果をQC分析
   ↓
2. 品質スコアを計算
   ↓
3. 最も高い総合スコアを持つ結果を選択
   ↓
4. マージ決定をログに記録
```

**並列開発型**:
```
1. 各worktreeのコードをQC分析
   ↓
2. 品質スコアを計算
   ↓
3. 最も高い総合スコアを持つworktreeを選択
   ↓
4. 選択されたworktreeをメインブランチにマージ
   ↓

```

## 📊 使用例

### 中央集権型でのQC統合

```rust
use codex_core::orchestration::{AutoOrchestrator, CollaborationStore, QcMerger, QcLogger};
use codex_core::agents::AgentRuntime;

let runtime = Arc::new(AgentRuntime::new(...));
let collaboration_store = Arc::new(CollaborationStore::new());
let orchestrator = AutoOrchestrator::new(runtime, collaboration_store, workspace_dir);

// オーケストレーション実行（QC統合済み）
let result = orchestrator.orchestrate(task_analysis, goal).await?;

// QC結果は自動的にログに記録される
// _docs/yyyy-mm-dd_HH-MM-SS_qc_merge_decision.md
```

### 並列開発型でのQC統合

```rust
use codex_core::orchestration::{ParallelOrchestrator, AgentTask, AgentType};

let orchestrator = ParallelOrchestrator::with_repo_path(".");

let tasks = vec![
    AgentTask {
        agent: AgentType::Codex,
        prompt: "Implement feature X".to_string(),
        worktree_path: None,
        timeout_seconds: Some(300),
        reasoning_effort: None,
    },
    AgentTask {
        agent: AgentType::GeminiCLI,
        prompt: "Implement feature X".to_string(),
        worktree_path: None,
        timeout_seconds: Some(300),
        reasoning_effort: None,
    },
];

// 並列実行（QC統合済み）
let results = orchestrator.execute_parallel(tasks).await?;

// 最も品質の高いworktreeが自動的にマージされる
// QC結果は自動的にログに記録される
```

## 🐛 修正した問題

### 1. 型の不一致
**問題**: `auto_orchestrator.rs`では`crate::agents::AgentResult`を使用しているが、`QcMerger`は`parallel_execution::AgentResult`を使用

**修正**: 型変換を追加して対応

### 2. モジュールエクスポート不足
**問題**: `qc_merger`と`qc_logger`モジュールがエクスポートされていない

**修正**: `mod.rs`にモジュールエクスポートを追加

### 3. インポート不足
**問題**: `parallel_execution.rs`で`QcMerger`と`QcLogger`のインポートがない

**修正**: 必要なインポートを追加
