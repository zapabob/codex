### 2. 新規検出エラー分析
コンパイルチェックで新たに15個のエラーが検出：

#### tokio関連エラー（9個）
```
error[E0432]: unresolved imports `tokio::io::AsyncBufReadExt`, `tokio::io::AsyncWriteExt`, `tokio::io::BufReader`
```
- **原因**: tokioの`io-util` featureが有効化されていない
- **解決**: Cargo.tomlに `features = ["io-util"]` を追加

```
error[E0432]: unresolved import `tokio::sync::mpsc`
error[E0432]: unresolved import `tokio::sync::Mutex`
```
- **原因**: tokioの`sync` featureが有効化されていない
- **解決**: Cargo.tomlに `features = ["sync"]` を追加

#### ToolInputSchema型ミスマッチ（3個）
```
error[E0308]: expected `ToolInputSchema`, found `Value`
```
- **原因**: `json!()` マクロの戻り値が `Value` だが `ToolInputSchema` が期待されている
- **解決**: 適切な型変換または `ToolInputSchema` の直接構築

#### その他のエラー
- stdoutのメソッド未解決（write_all, flush）
- ライフタイム関連のSized制約エラー

### 3. Cargo.toml修正
#### 現在の依存関係
```toml
[dependencies]
anyhow = "1.0"

serde_json = "1.0"
tokio = { version = "1.0", features = ["full"] }

```

#### 必要な修正
```toml
[dependencies]
anyhow = "1.0"
mcp-types = { path = "../mcp-types" }
serde_json = "1.0"
tokio = { version = "1.0", features = ["full", "io-util", "sync"] }
tracing = "0.1"
tracing-subscriber = "0.3"
```

### 4. ToolInputSchema修正
#### 現在のコード
```rust
input_schema: json!({
    "type": "object",
    "properties": {
        // ...
    }
}),
```

#### 修正案
```rust
input_schema: ToolInputSchema {
    r#type: "object".to_string(),
    properties: Some(serde_json::json!({
        // ...
    })),
},
```

## 技術的考察

### tokio Feature問題
- tokio 1.xでは高度な機能がfeature flagで制御されている
- `io-util`: AsyncBufReadExt, AsyncWriteExt, BufReader
- `sync`: mpsc, Mutexなどの同期プリミティブ
- `full`: すべての機能を有効化（ただし重い）

### ToolInputSchema設計
- MCP仕様に基づくスキーマ定義
- JSON Schema形式のツール入力定義
- serde_json::Value vs 構造体定義のトレードオフ

### エラー修正の優先順位
1. **高**: 依存関係/feature設定（Cargo.toml）
2. **中**: 型定義/構造体修正（ToolInputSchema）
3. **低**: メソッド呼び出し修正（stdout, ライフタイム）

## 結論

最初の修正で主要な3つのエラーを解決したが、新たに15個の関連エラーが検出された。これらは主にtokioのfeature設定と型定義の問題である。
