## 実装方針

### 原則

- **公式優先**: 公式の実装を採用し、独自機能は公式のAPIに合わせて再実装
- **後方互換性**: 既存の独自機能のAPIは可能な限り維持
- **段階的移行**: 一度に全て変更せず、段階的に移行

## 実装手順

### Phase 1: 公式変更の取得とマージ

1. **upstream/mainのマージ**

- `git fetch upstream`
- `git merge upstream/main` (競合解決は公式優先)
- マージ後のビルド確認

2. **削除された機能の対応**

- `undo`機能: 独自実装があれば削除または非推奨化
- `rmcp`機能: 独自実装があれば削除または非推奨化
- `plan`機能: 公式では削除されているが、独自実装は維持（非公式機能として）

### Phase 2: 依存関係の更新

1. **Cargo.tomlの更新**

- clap 4.5.53への更新
- landlock 0.4.4への更新
- openssl-sys 0.9.111への更新
- test-log 0.2.19への更新
- tracing-opentelemetry 0.32.0への更新

2. **互換性確認**

- 各依存関係の破壊的変更を確認
- 必要に応じてコードを修正

### Phase 3: バグ修正の取り込み

1. **TUI2の修正**

- トランスクリプトマウス選択境界の修正 (#8419)
- スクロール入力の調整 (#8357)

2. **パニック修正**

- アルファ版でのパニック修正 (#8406)

3. **テスト修正**

- TUI2: ANSI for VT100 testsの再有効化 (#8423)

### Phase 4: 独自機能の公式API準拠

1. **orchestrationモジュールの整理**

- 公式のAPIに合わせてインターフェースを調整
- 内部実装は独自機能を維持

2. **sub-agent systemの整理**

- 公式のskills APIに合わせて調整
- 独自の並列実行機能は維持

3. **plan機能の非公式化**

- 公式では削除されているため、非公式機能として明確化
- ドキュメントに「zapabob独自機能」と明記

### Phase 5: ビルドとテスト

1. **ビルド確認**

- `cargo build --all-features` でビルドエラーを確認
- エラーがあれば修正

2. **テスト実行**

- `cargo test --all-features` でテストを実行
- 失敗したテストを修正

3. **リンター確認**

- `cargo clippy --all-features -- -D warnings` で警告を確認
- 警告があれば修正

## リスクと対策

### リスク1: マージ競合

- **対策**: 公式優先で解決し、独自機能は後で再実装

### リスク2: ビルドエラー

- **対策**: 段階的にマージし、各段階でビルド確認

### リスク3: テスト失敗

- **対策**: テストを修正し、独自機能のテストは維持

### リスク4: 後方互換性の破壊

- **対策**: 独自機能のAPIは可能な限り維持し、必要に応じて非推奨化
