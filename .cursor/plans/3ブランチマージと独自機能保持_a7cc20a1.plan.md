## 実装手順

### Phase 1: 現状確認とバックアップ

1. **作業前のバックアップ作成**

- `git branch backup-before-3way-merge-$(date +%Y%m%d-%H%M%S)`
- 現在の作業ツリーの状態を保存

2. **各ブランチの差分確認**

- `git diff merge-upstream-2025-12-20..origin/main` - origin/mainの追加変更を確認
- `git diff merge-upstream-2025-12-20..main` - mainの追加変更を確認
- コンフリクト予測ファイルをリストアップ

3. **独自機能ファイルの保護リスト作成**

- Deep Research関連ファイル
- Orchestration関連ファイル
- agents関連ファイル
- plan機能関連ファイル

### Phase 2: 3ブランチマージ実行

1. **origin/mainをマージ**

- `git merge origin/main --no-commit`
- コンフリクト発生時は独自機能を優先（`-X ours`を検討）
- GUI-CLI bridge統合などの新機能を保持

2. **mainをマージ**

- `git merge main --no-commit`
- 既にorigin/mainに含まれている場合はスキップ
- 追加の変更があれば統合

3. **コンフリクト解決戦略**

- **公式のコア機能変更**: 公式を優先
- **zapabob独自機能**: 完全保持
- **両方に存在する機能**: 統合を試みる（例: skills機能）
- **設定ファイル**: zapabob版を優先（独自設定保持）

### Phase 3: コンフリクト解消

1. **コンフリクトファイルの分類**

- コア機能（公式優先）: `codex-rs/core/src/codex.rs`, `codex-rs/core/src/client.rs` など
- 独自機能（完全保持）: `codex-rs/core/src/orchestration/`, `codex-rs/core/src/agents/` など
- 設定ファイル（zapabob優先）: `config.toml`, `.gitignore` など
- 共通機能（統合）: skills機能、MCP関連

2. **コンフリクト解決**

- 各ファイルごとに適切な戦略を適用
- 解決後、`git add`でステージング

3. **ビルドエラー確認**

- `cargo check --all-features` で即座にエラー確認
- エラーがあれば修正

### Phase 4: 高速差分ビルドとインストール

1. **ビルド環境最適化**

- `CARGO_TARGET_DIR=target/fast` で高速ビルドディレクトリ設定
- `RUSTC_WRAPPER=sccache` でキャッシュ有効化（利用可能な場合）

2. **差分ビルド実行**

- `cargo build -p codex-cli -p codex-tui --release`
- 変更されたクレートのみ再ビルド
- 進捗をtqdm風に視覚化（Pythonスクリプト使用）

3. **バイナリ上書きインストール**

- `cargo install --path codex-rs/cli --force`
- `cargo install --path codex-rs/tui --force`
- 既存のバイナリを上書き

### Phase 5: 実機テスト

1. **基本動作確認**

- `codex --version` - バージョン確認
- `codex --help` - ヘルプ表示確認

2. **機能テスト**

- skills機能の動作確認
- Deep Research機能の動作確認
- Orchestration機能の動作確認
- MCPサーバー接続確認

3. **統合テスト**

- TUI起動確認
- CLIコマンド実行確認
- エージェント呼び出し確認

4. **エラー確認**

- ログファイルの確認
- パニックやエラーの有無を確認
