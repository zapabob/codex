## 実装計画

### Phase 1: 公式リポジトリ統合（最優先）

#### 1.1 Upstream最新版の取得と差分分析

**手順**:

1. `git fetch upstream`で最新を取得（既に実行済み）
2. `git log main..upstream/main --oneline`で差分確認
3. コンフリクト予測のため主要ファイルの差分を確認

**対象コミット**:

- セキュリティ修正: `9f7936569`, `30eb655ad`
- バグフィクス: `fef3e36f6`, `1609f6aa8`, `a90ab789c`
- 新機能: `3878c3dc7` (SQLite), `996e09ca2` (RequestRule)

#### 1.2 マージ戦略の実行

**方針**:

- 公式の変更を優先（コア機能、バグフィクス、セキュリティ修正）
- 独自機能は`#[cfg(feature = "custom-features")]`で保護
- コンフリクト時は公式版を採用し、独自機能は別モジュールで保持

**マージ手順**:

```powershell
# バックアップブランチ作成
git checkout -b backup-before-upstream-merge

# upstream/mainをマージ
git checkout main
git merge upstream/main --no-ff -m "feat: Merge upstream/main with custom features preservation"
```

**コンフリクト解決方針**:

- `codex-rs/core/src/` - 公式版を優先、独自機能は条件付きコンパイルで保護
- `codex-rs/cli/src/` - 公式版を優先、独自コマンドは`custom-features`で保護
- `.codex/agents/` - 完全保持（公式に存在しない）
- `codex-rs/deep-research/` - 完全保持（公式に存在しない）
- `codex-rs/gemini-cli-mcp-server/` - 完全保持（公式に存在しない）

#### 1.3 ビルド検証

**検証手順**:

```powershell
cd codex-rs
cargo build --workspace --features custom-features
cargo check --workspace --features custom-features
cargo test --workspace --features custom-features
cargo clippy --workspace --features custom-features -- -D warnings
```
