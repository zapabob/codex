# QCエージェント統合と品質ベースマージ実装計画

## 概要

中央集権型（Central）と並列開発型（Worktree）の両方で、QCエージェントをサブエージェントとして統合し、QC管理・量子最適化・数理最適化による品質スコア計算を行い、最も品質の高いコードをログに記録してマージする機能を実装する。

## 実装内容

### 1. AgentTypeにQcAgentを追加

**ファイル**: `codex-rs/core/src/orchestration/parallel_execution.rs`

- `AgentType` enumに`QcAgent`バリアントを追加
- `execute_agent`メソッドにQCエージェント実行ロジックを追加
- QCエージェントは他のエージェント（Codex, GeminiCLI等）と並列実行
```rust
#[derive(Debug, Clone, Copy, Serialize, Deserialize, PartialEq, Eq, Hash)]
#[serde(rename_all = "lowercase")]
pub enum AgentType {
    Codex,
    GeminiCLI,
    Claudecode,
    QcAgent,  // 追加
}
```


### 2. QCエージェント実行ロジック実装

**ファイル**: `codex-rs/core/src/orchestration/parallel_execution.rs`

- `run_qc_agent`メソッドを追加
- `QcAgent::analyze()`を呼び出してコード品質分析を実行
- 分析対象は他のエージェントが生成したコード
- QC結果（QcReport, QualityScore）を返却

### 3. 品質スコアベースのマージ機能実装

**ファイル**: `codex-rs/core/src/orchestration/qc_merger.rs` (新規)

- `QcMerger`構造体を作成
- 中央集権型用: 複数エージェントの結果をQC評価して最も品質の高いものを選択
- 並列開発型用: 各worktreeの結果をQC評価して最も品質の高いworktreeをマージ
- 品質スコア比較ロジック（`QualityScore::overall`を使用）
```rust
pub struct QcMerger {
    qc_agent: Arc<QcAgent>,
}

impl QcMerger {
    pub async fn select_best_central(&self, results: Vec<AgentResult>) -> Result<AgentResult>;
    pub async fn select_best_worktree(&self, worktrees: Vec<WorktreeInfo>) -> Result<WorktreeInfo>;
}
```


### 4. 中央集権型オーケストレーションへのQC統合

**ファイル**: `codex-rs/core/src/orchestration/auto_orchestrator.rs`

- `orchestrate`メソッドを修正
- 他のエージェント実行と並列でQCエージェントを実行
- QC結果を`OrchestratedResult`に含める
- `QcMerger`を使用して最も品質の高い結果を選択

### 5. 並列開発型（Worktree）へのQC統合

**ファイル**: `codex-rs/core/src/orchestration/parallel_execution.rs`

- `execute_parallel`メソッドを修正
- 各worktreeでエージェント実行後にQC分析を実行
- QC結果を`AgentResult`に含める
- `QcMerger`を使用して最も品質の高いworktreeを選択してマージ

### 6. QC結果のログ記録機能

**ファイル**: `codex-rs/core/src/orchestration/qc_logger.rs` (新規)

- `QcLogger`構造体を作成
- QC結果を実装ログ形式で`_docs/`ディレクトリに保存
- 品質スコア、最適化結果、推奨事項を記録
- マージ決定の根拠を記録
```rust
pub struct QcLogger {
    logs_dir: PathBuf,
}

impl QcLogger {
    pub async fn log_qc_result(&self, report: &QcReport, merge_decision: &str) -> Result<PathBuf>;
    pub async fn log_merge_decision(&self, selected: &str, scores: &HashMap<String, QualityScore>) -> Result<PathBuf>;
}
```


### 7. DevelopmentModeへのQC設定追加

**ファイル**: `codex-rs/core/src/orchestration/development_mode.rs`

- `DevelopmentMode`にQC設定を追加
- QCエージェントの有効/無効
- QC分析のタイミング（並列実行 vs 実行後）
```rust
pub enum DevelopmentMode {
    Central {
        merge_strategy: MergeStrategy,
        dynamic_conflict_detection: bool,
        enable_qc: bool,  // 追加
    },
    Worktree {
        num_worktrees: usize,
        auto_merge_winner: bool,
        enable_qc: bool,  // 追加
    },
}
```


## 実装順序

1. `AgentType`に`QcAgent`を追加
2. QCエージェント実行ロジック実装
3. `QcMerger`実装（品質スコアベースのマージ）
4. `QcLogger`実装（ログ記録）
5. 中央集権型オーケストレーションへの統合
6. 並列開発型への統合
7. `DevelopmentMode`へのQC設定追加

## テスト項目

- QCエージェントが他のエージェントと並列実行されること
- 品質スコアが正しく計算されること
- 最も品質の高いコードが選択されること
- QC結果がログに記録されること
- 中央集権型と並列開発型の両方で動作すること
