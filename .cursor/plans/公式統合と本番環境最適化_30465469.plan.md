### 1.3 マージ実行

**作業ブランチ作成**:

```powershell
git checkout -b upstream-sync-$(Get-Date -Format 'yyyy-MM-dd')
```

**マージ実行**:

```powershell
git fetch upstream
git merge upstream/main --no-ff -m "Merge upstream/main: 公式リポジトリの最新を取り込み"
```

**コンフリクト解決方針**:

- 公式の変更を優先（セキュリティ修正、バグフィクス）
- 独自機能は`custom-features`フラグで保護されているため、コンフリクトは最小限
- コンフリクト発生時は、公式の変更を採用し、独自機能は別コミットで再適用

**ビルド検証**:

```powershell
cargo build --features custom-features
cargo test --features custom-features
```

**テスト実行**:

```powershell
cargo test --features custom-features --workspace
```

## リスクと対策

**リスク1**: マージコンフリクトが大量発生

- **対策**: 段階的なマージ（重要なコミットから順次）、`custom-features`フラグで保護された独自機能は影響を受けにくい

**リスク2**: ビルドエラーが発生

- **対策**: マージ後すぐにビルド検証、エラーがあれば即座に修正

**リスク3**: テストが失敗

- **対策**: テスト失敗の原因を特定し、公式の変更に合わせてテストを更新
