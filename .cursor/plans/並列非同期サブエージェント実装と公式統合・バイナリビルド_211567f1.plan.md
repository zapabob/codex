### Task 1: 並列非同期サブエージェント機能の実装・改善

**目的**: 既存の並列非同期サブエージェント機能を強化し、エラーハンドリング、進捗追跡、リソース制限を追加

**実装ファイル**: 

- `codex-rs/core/src/agents/runtime.rs` (更新)
- `codex-rs/core/src/agents/parallel_executor.rs` (新規作成)

**改善内容**:

1. **エラーハンドリング強化**
  - 個別エージェントの失敗が全体に影響しないように改善
  - 部分的な成功結果の返却
  - エラー詳細の記録
2. **進捗追跡**
  - 各エージェントの進捗をリアルタイムで追跡
  - 進捗イベントの通知機能
  - 完了率の可視化
3. **リソース制限**
  - 同時実行数の制限
  - メモリ使用量の監視
  - タイムアウト機能
4. **パフォーマンス最適化**
  - タスクキューによる優先度管理
  - 負荷分散の改善
  - キャッシング機能

**実装例**:

```rust
// codex-rs/core/src/agents/parallel_executor.rs
pub struct ParallelExecutor {
    max_concurrent: usize,
    timeout: Option<Duration>,
    progress_tx: Option<mpsc::Sender<ProgressEvent>>,
}

impl ParallelExecutor {
    pub async fn execute_parallel(
        &self,
        agents: Vec<AgentTask>,
    ) -> Result<Vec<AgentResult>> {
        // セマフォによる同時実行数制限
        let semaphore = Arc::new(Semaphore::new(self.max_concurrent));
        
        // 各エージェントを並列実行
        let handles: Vec<_> = agents.into_iter()
            .map(|task| {
                let sem = semaphore.clone();
                let progress = self.progress_tx.clone();
                tokio::spawn(async move {
                    let _permit = sem.acquire().await?;
                    Self::execute_with_progress(task, progress).await
                })
            })
            .collect();
        
        // 結果を集約（エラーがあっても続行）
        let mut results = Vec::new();
        for handle in handles {
            match handle.await {
                Ok(Ok(result)) => results.push(result),
                Ok(Err(e)) => results.push(AgentResult::error(e)),
                Err(e) => results.push(AgentResult::error(e.into())),
            }
        }
        
        Ok(results)
    }
}
```

### Task 2: 公式リポジトリの最新機能・脆弱性更新・バグフィクス取り込み

**目的**: upstream/mainの最新変更を取り込み、独自機能を維持

**実装手順**:

1. **差分分析**
  ```powershell
   git fetch upstream
   git log main..upstream/main --oneline
   git diff --stat main upstream/main
  ```
2. **重要なコミットの特定**
  - セキュリティ修正（CVE対応）
  - バグフィクス
  - 脆弱性更新
  - 新機能追加
3. **マージ実行**
  ```powershell
   git checkout -b upstream-sync-$(Get-Date -Format 'yyyy-MM-dd')
   git merge upstream/main --no-ff -m "Merge upstream/main: 公式リポジトリの最新を取り込み"
  ```
4. **コンフリクト解決方針**
  - 公式の変更を優先（セキュリティ修正、バグフィクス）
  - 独自機能は `#[cfg(feature = "custom-features")]` で保護
  - コンフリクト発生時は公式の変更を採用し、独自機能は別コミットで再適用
5. **ビルド検証**
  ```powershell
   cargo build --features custom-features
   cargo test --features custom-features
  ```

### Task 3: 公式機能と独自機能の比較分析と統合

**目的**: 公式機能と独自機能を比較し、同等の場合は公式機能に独自機能の利点を導入、公式機能の欠点を独自機能で補完

3. **Orchestration機能**

  - 独自: 並列実行、QC統合、worktree管理
  - **統合方針**: 独自機能を保持（公式に同等機能がない）
