# TUI公式リポジトリマージ計画

## 概要

OpenAI/codex公式リポジトリ（upstream/main）の最新TUI機能を取り込みつつ、以下の独自機能を保持してマージします：

- GPU統計表示機能（`gpu_stats.rs`）
- カスタムプロンプト機能（`custom_prompt_view.rs`）
- Delegate/Orchestrate/Research/Hookコマンド（TUI実装）
- その他の独自機能

## 実装ステップ

### Phase 1: 下準備と差分確認

1. **upstream/mainの最新取得**

- `git fetch upstream main` で最新コミットを取得
- `git log upstream/main --oneline -- codex-rs/tui -20` で最新のTUI変更を確認

2. **現状の独自機能を特定**

- `gpu_stats.rs` - GPU統計表示（Windows AI統合）
- `custom_prompt_view.rs` - カスタムプロンプトUI
- `chatwidget.rs` の `zapabob独自` コメント部分
- `main.rs` の簡易実装（公式はclapベース）

3. **差分確認**

- `git diff upstream/main -- codex-rs/tui` で全体差分を確認
- コンフリクトが発生しそうなファイルを特定

### Phase 2: ours優先マージ

1. **マージ実行**

- `git merge upstream/main -X ours` でours優先マージ
- これにより独自機能が優先的に保持される

2. **コンフリクト解決**

- コンフリクトが発生したファイルを個別に確認
- 主な対象ファイル：
- `codex-rs/tui/src/lib.rs` - メインライブラリ
- `codex-rs/tui/src/main.rs` - エントリーポイント（独自実装を保持）
- `codex-rs/tui/src/chatwidget.rs` - Delegateコマンドなど
- `codex-rs/tui/src/bottom_pane/mod.rs` - GPU統計統合
- `codex-rs/tui/Cargo.toml` - 依存関係

3. **公式の新機能を手動統合**

- 公式の新機能を確認し、独自機能と競合しない範囲で統合
- 必要に応じて独自機能を公式の新APIに合わせて更新

### Phase 3: 独自機能の統合確認

1. **GPU統計機能の確認**

- `gpu_stats.rs` が正しく統合されているか確認
- `bottom_pane/mod.rs` のGPU統計表示ロジックを確認
- Windows AI統合が動作するか確認

2. **カスタムプロンプト機能の確認**

- `custom_prompt_view.rs` が正しく統合されているか確認
- `chat_composer.rs` のカスタムプロンプト処理を確認

3. **Delegateコマンドの確認**

- `chatwidget.rs` の `zapabob独自` コメント部分を確認
- TUIでの実装状況を確認（CLIへのフォールバックは維持）

### Phase 4: ビルドと依存関係更新

1. **依存関係の確認**

- `codex-rs/tui/Cargo.toml` を確認
- 公式の新機能で追加された依存関係を確認
- 独自機能に必要な依存関係が維持されているか確認

2. **ビルド実行**

- `cd codex-rs && cargo build --release -p codex-tui` でビルド
- ビルドエラーがあれば修正

3. **リンター確認**

- `just fix -p codex-tui` でリンターエラーを修正
- `just fmt` でフォーマット

### Phase 5: 起動確認とテスト

1. **TUI起動確認**

- `codex tui` または `codex-tui` でTUIを起動
- 基本的な画面表示を確認

2. **機能確認**

- GPU統計表示が動作するか確認（Windows環境）
- カスタムプロンプト機能が動作するか確認
- Delegateコマンドが適切にフォールバックするか確認
- 公式の新機能（最新のslash commandsなど）が動作するか確認

3. **テスト実行**

- `cargo test -p codex-tui` でテストを実行
- 失敗したテストがあれば修正

### Phase 6: 実装ログ作成

1. **ログ作成**

- `_docs/` に `yyyy-mm-dd_TUI公式マージ完了.md` を作成
- マージ内容、保持した独自機能、統合した公式機能、ビルド結果、起動確認結果を記録

## 注意事項

1. **ours優先マージの影響**

- `-X ours` により、コンフリクト時は常にローカルの変更が優先される
- 公式の新機能は手動で統合する必要がある

2. **独自機能の保持**

- GPU統計機能はWindows AI統合に依存
- カスタムプロンプト機能は公式のカスタムプロンプト機能と統合が必要な可能性

3. **main.rsの扱い**

- 現在の簡易実装を保持するか、公式のclapベース実装に置き換えるか判断が必要

4. **ビルドエラーの可能性**

- 公式の新機能でAPIが変更されている可能性
- 依存関係のバージョン不一致の可能性

- `codex-rs/tui/Cargo.toml` - 依存関係
