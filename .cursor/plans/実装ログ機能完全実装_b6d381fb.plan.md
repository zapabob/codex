# 実装ログ機能完全実装計画

## 現状分析

### 既存実装

- `codex-rs/core/src/implementation_log.rs`: 基本的な実装ログ機能が実装済み
- `scripts/implementation_logger.py`: Pythonスクリプトが存在
- 起動時の実装ログ読み込み: `exec/src/lib.rs` の397行目で実装済み
- 音声再生関数: `play_completion_sound()` が存在

### 不足している機能

1. **MCP経由の日時取得**: Pythonスクリプトでフォールバックのみ
2. **Plan/Agent終了時の音声再生**: 統合されていない
3. **実装ログの自動生成**: 手動呼び出しが必要

## 実装タスク

### 1. PythonスクリプトでMCP経由の日時取得を実装

**ファイル**: `scripts/implementation_logger.py`

- MCPクライアント経由で `codex-datetime` ツールを呼び出す機能を追加
- 環境変数や設定ファイルからMCP接続情報を取得
- フォールバックとしてシステム日時を使用（既存の実装を維持）

**実装方法**:

- MCPサーバーへの接続を確立
- `codex-datetime` ツールを呼び出し
- エラー時は既存のフォールバック処理を使用

### 2. Plan/Agent終了時の音声再生を統合

**ファイル**: `codex-rs/exec/src/event_processor_with_human_output.rs`

- `TaskComplete` イベント処理時（224行目付近）に `play_completion_sound()` を呼び出す
- `ShutdownComplete` イベント処理時（554行目付近）にも呼び出す（念のため）

**実装方法**:

```rust
EventMsg::TaskComplete(TaskCompleteEvent { last_agent_message }) => {
    // 既存の処理...
    
    // 音声再生を非同期で実行（ブロックしない）
    let _ = codex_core::implementation_log::play_completion_sound().await;
    
    return CodexStatus::InitiateShutdown;
}
```

### 3. Plan/Agent完了時に実装ログを自動生成

**ファイル**: `codex-rs/exec/src/event_processor_with_human_output.rs`

- `TaskComplete` イベント処理時に実装ログを自動生成
- タスクの内容を要約してログに記録
- エラー時はログに記録するが処理は継続

**実装方法**:

- `TaskComplete` イベントからタスク情報を抽出
- `create_implementation_log()` を呼び出してログを生成
- 機能名、タスク説明、実装詳細を適切に設定

### 4. 実装ログの内容を充実させる

**ファイル**: `scripts/implementation_logger.py`

- 実装ログのテンプレートを改善
- より詳細な情報を記録（変更されたファイル、実行時間など）
- なんJ風コメントを充実

### 5. エラーハンドリングの強化

**ファイル**: `codex-rs/core/src/implementation_log.rs`

- 各関数のエラーハンドリングを改善
- ログ出力を適切に設定
- フォールバック処理を確実に動作させる

## 実装順序

1. PythonスクリプトでMCP経由の日時取得を実装（フォールバック維持）
2. Plan/Agent終了時の音声再生を統合
3. Plan/Agent完了時に実装ログを自動生成
4. 実装ログの内容を充実
5. エラーハンドリングの強化
6. テストと動作確認

## 注意事項

- 音声再生は非同期で実行し、メイン処理をブロックしない
- 実装ログの自動生成が失敗しても、メイン処理は継続する
- MCP接続が失敗した場合は、フォールバック処理を使用
- 既存の機能を壊さないように注意
