# Rust2024ベストプラクティス本番環境実装計画

## 現状分析

### 完了済み

- ワークスペースレベルで`edition = "2024"`が設定済み
- リリースプロファイル設定（`lto = "fat"`, `codegen-units = 1`）
- OpenTelemetry統合が存在
- 監査ログシステムが存在
- `unwrap_used = "deny"`が設定済み

### 改善が必要な項目

1. 一部クレートがまだ`edition = "2021"`を使用（`windows-sandbox-rs`, `utils/pty`）
2. 一部のコードで`unwrap()`や`expect()`が使用されている（特にテストコード）
3. エラーハンドリングの一貫性が不足
4. セキュリティ監査が必要
5. パフォーマンスプロファイリングが不足
6. 本番環境向けのログ戦略が未整備

## 実装計画

### Phase 1: Edition 2024への完全移行

**目標**: 全クレートをRust 2024 editionに移行

**対象ファイル**:

- `codex-rs/windows-sandbox-rs/Cargo.toml` - `edition = "2021"` → `edition = "2024"`
- `codex-rs/utils/pty/Cargo.toml` - `edition = "2021"` → `edition = "2024"`

**作業内容**:

1. 各クレートの`Cargo.toml`を更新
2. 移行に伴う互換性問題を確認・修正
3. ビルド検証（`cargo build --release`）
4. テスト実行（`cargo test`）

### Phase 2: エラーハンドリングの改善

**目標**: `unwrap()`と`expect()`を適切なエラーハンドリングに置き換え

**対象ファイル**:

- `codex-rs/core/src/git4d_accelerated.rs` - 複数の`unwrap()`使用箇所
- その他の`unwrap()`/`expect()`使用箇所

**改善パターン**:

```rust
// Before
let sessions = SESSIONS.read().unwrap();

// After
let sessions = SESSIONS.read()
    .map_err(|e| anyhow::anyhow!("Failed to acquire read lock: {}", e))?;
```

**実装方針**:

1. 本番コードでの`unwrap()`/`expect()`を`Result`型に置き換え
2. テストコードは`unwrap()`使用可（`#[cfg(test)]`内）
3. エラーメッセージを明確化
4. エラーコンテキストを追加（`anyhow::Context`使用）

### ビルド検証

```bash

cargo build --release --workspace

# 特定クレートのビルド
cargo build --release -p codex-core -p codex-cli

# カスタム機能付きビルド
cargo build --release --features custom-features
```

### テスト検証

```bash
# 全テスト実行
cargo test --workspace

# リリースモードでのテスト
cargo test --release

# カバレッジ測定
cargo test --workspace --all-features
cargo install cargo-tarpaulin
cargo tarpaulin --workspace --out Html
```

### リンター検証

```bash
# Clippy実行

```
